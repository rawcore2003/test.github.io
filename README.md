# یادمان شهدا | نسخه استاتیک برای GitHub Pages

این پروژه با HTML، CSS و JavaScript خالص ساخته شده است. برای اجرای سایت روی GitHub Pages به Node.js یا سرور اختصاصی نیاز نیست. اسکریپت ساخت از Python استاندارد استفاده می‌کند و فقط در GitHub Actions اجرا می‌شود.

## امکانات
- فهرست شهدا، جست‌وجو و مرتب‌سازی
- صفحه اختصاصی هر شهید با زندگی‌نامه، وصیت‌نامه، خاطرات، تصاویر، فیلم، صوت و اسناد
- پنل مدیریت برای افزودن، ویرایش و حذف
- ذخیره اطلاعات در `data/martyrs.json`
- ثبت URL رسانه‌ها؛ فایل‌ها در فضای ابری باقی می‌مانند
- انتشار خودکار با GitHub Actions پس از commit داده‌ها

## راه‌اندازی اولیه

1. یک مخزن GitHub با نام دلخواه بساز و تمام فایل‌های این پروژه را در شاخه `main` قرار بده.
2. فایل `config.js` را باز کن و `YOUR_GITHUB_USERNAME` و `YOUR_REPOSITORY_NAME` را با نام کاربری و نام مخزن خودت جایگزین کن.
3. در GitHub وارد Settings → Pages شو و در بخش Build and deployment، گزینه **GitHub Actions** را به‌عنوان Source انتخاب کن.
4. تغییرات را commit و push کن. از تب Actions اجرای workflow را بررسی کن.
5. نشانی سایت معمولاً `https://USERNAME.github.io/REPOSITORY/` خواهد بود.

## ورود امن به پنل مدیریت

1. در GitHub به Settings → Developer settings → Personal access tokens → Fine-grained tokens برو.
2. یک توکن بساز که فقط به همین مخزن دسترسی داشته باشد.
3. Repository permissions را روی **Contents: Read and write** قرار بده. Metadata دسترسی read-only پیش‌فرض است.
4. توکن را فقط در صفحه `admin.html` وارد کن. این پروژه آن را در localStorage، cookie یا فایل‌های مخزن ذخیره نمی‌کند.
5. پنل هویت GitHub را بررسی می‌کند و فقط حسابی را می‌پذیرد که نامش با `owner` در `config.js` برابر باشد.

**مهم:** توکن را در کد، پیام commit، فایل تنظیمات یا اسکرین‌شات قرار نده. اگر احتمال افشای توکن وجود داشت، آن را از GitHub لغو کن و توکن جدید بساز. برای امنیت بیشتر، از توکن کوتاه‌عمر و فقط دسترسی همان مخزن استفاده کن.

## روش کار پنل

- برای افزودن یا ویرایش، فرم را تکمیل و «ذخیره تغییرات در GitHub» را بزن.
- هر رسانه را به‌صورت یک URL کامل `https://...` وارد کن. در فیلدهای چندرسانه‌ای، هر لینک در یک خط قرار می‌گیرد.
- ذخیره، یک commit جدید در شاخه `main` ایجاد می‌کند. workflow با push اجرا می‌شود و نسخه سایت را منتشر می‌کند.
- دکمه «بروزرسانی و انتشار سایت» وضعیت اجرای Actions را نشان می‌دهد؛ انتشار مجدد بدون commit جدید معمولاً لازم نیست. برای اجرای دستی، در تب Actions workflow را با Run workflow اجرا کن.

## محدودیت‌ها و نکات امنیتی

- GitHub Pages عمومی است؛ فایل‌های HTML، JS و JSON سایت برای همه قابل دریافت‌اند. اطلاعات خصوصی اشخاص یا اسناد محرمانه را در JSON قرار نده.
- `admin.html` از نظر محتوا noindex است، اما این به‌تنهایی کنترل دسترسی نیست. امنیت نوشتن اطلاعات بر پایه توکن GitHub و بررسی حساب مالک است.
- برای امنیت بالاتر سازمانی می‌توان در مرحله بعد احراز هویت مبتنی بر GitHub OAuth با یک سرویس واسط امن افزود؛ اما آن راهکار دیگر کاملاً بدون سرویس سمت سرور نخواهد بود.
- لینک‌های فضای ابری باید عمومی یا دارای مجوز نمایش برای بازدیدکنندگان باشند. لینک‌های موقت/خصوصی برای نمایش عمومی مناسب نیستند.
- برخی سرویس‌ها نمایش مستقیم ویدئو یا تصویر در سایت را با محدودیت CORS یا hotlink مسدود می‌کنند. در این حالت از لینک embed یا دامنه‌ای استفاده کن که نمایش عمومی را مجاز می‌کند.
- محتوای ورودی به‌صورت متن escape می‌شود و URLهای رسانه‌ای به پروتکل http/https محدود شده‌اند.

## توسعه محلی

با هر وب‌سرور استاتیک می‌توان پروژه را اجرا کرد. برای نمونه Python:
`python3 -m http.server 8000`
سپس `http://localhost:8000` را باز کن. باز کردن مستقیم فایل HTML با `file://` به‌دلیل محدودیت fetch برای JSON توصیه نمی‌شود.
